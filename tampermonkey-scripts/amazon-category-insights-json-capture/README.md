# Amazon 类目洞察数据采集器 v7.0.6

本版在v7.0.5基础上改进整次任务日志、目录请求上下文、结束清理和动态统计。

## v7.0.6 本次改进

- 以每次“开始抓取/继续任务/导入重采”到任务结束为一个运行日志段，不按每个50节点ZIP拆日志。
- 当次完整日志保留全部记录，不再受旧版3000条缓冲限制；界面仍只显示最近800条，控制DOM开销。“清空日志”仅清空可见区域，不丢弃当次完整导出内容。
- 任务完成后先完成数据ZIP及必要的失败清单导出，再自动触发完整运行log下载，随后清空完整缓冲及可见日志区域，并重置请求编号。下次启动请求编号重新从1开始，唯一请求ID仍带任务/会话信息。
- 自动运行日志导出异常时保留完整缓冲和计数；“下载日志”可重试。下一次任务开始前也会先重试保存，避免直接覆盖未保存记录。
- 正常完成后释放目录缓存及临时防回填集合；旧的在途页面目录响应不得在清理后重新填充缓存。保留任务总体统计、失败重采元数据。中断或异常结束时保留未完成数据及续采所需缓存，只在日志成功导出后重置请求编号。
- getFilters发送与响应日志展示实际请求的目录类型、商城/类别/商品类型代码，不再沿用上一业务节点的路径。
- 浮窗动态显示“已下载 N · 失败 M”。已下载统计本次成功触发下载并清理的完整节点；失败统计最终整节点失败的唯一完整路径，不把可恢复的单次超时计入最终失败。新任务重置两项，完成后保留末次汇总供查看。

日志中“已下载/已保存”均不能证明文件已经实际落盘，请检查浏览器下载记录。自动日志成功触发后会清空缓冲，不能从脚本取回此前已清空的运行日志。

## 整节点成功与失败

- performance必须有有效主数据；其他三个接口可以有数据、明确无数据或HTTP204无正文。合法空数据不是失败，双null Features空响应继续兼容。
- 某接口最终失败时，该节点不能进入数据ZIP。即时重试及符合条件的一次延后补采均完成后仍未成功，记录该节点到失败清单，清除其全部已成功JSON、批次及单节点完成记录，并继续后续节点。
- 未知结构、HTTP400/404等不可重试错误不会反复请求，直接将该节点记入清单。网络错误、超时和可重试5xx沿用兜底策略。
- 处理中节点不能手动导出不完整ZIP。已确认的失败节点会从数据列表移除，浮窗显示“待重采”数量。
- 总数量预算按完整成功的节点计算，失败节点不占成功名额。每批默认50个成功节点，最后不足一批时收尾下载。下载成功触发后真实删除本地节点记录，不保留历史补下载副本。
- 失败节点仅保留重采所需的路径、失败原因、接口状态和逐次尝试信息；不保留已成功或失败接口的响应正文。该失败元数据存于当前任务，供导出清单与刷新恢复使用。

## 失败重采 log

只有最终失败数量大于0时，任务结束才自动触发下载：`失败重采_v7.0.6_失败N条_时间戳.log`。失败0条不再下载该文件。另有“下载失败重采 log”按钮，仅在存在失败节点且任务已结束时可用。整次运行日志仍然自动下载，与失败清单独立。

清单包含：失败数量、商城/类别/商品类型/关键词名称与代码、节点ID、失败接口、原因、HTTP状态及尝试次数；同时附机器可读JSON信息，供直接导入。请保留整个文件，不要只复制可读部分。

手动终止、登录失效或限流停止时，清单会明确任务状态及另有多少待处理/待下载记录。它只列“已经确定最终失败”的节点，不包含尚未遍历的节点。当前未完成节点可用“继续未完成任务”续采，不能把一份0失败的中断清单理解为全部采集成功。

## 导入后自动重采

1. 在浮窗点击“导入失败重采 log”，选择上面导出的`.log`文件。
2. 校验通过后自动开始，不需要再点击开始。只处理清单中的唯一完整路径，不遍历其他目录，也不依赖GUI当前选中项。
3. 因失败节点的原成功数据已丢弃，重采会重新请求该节点全部四个接口，而不是仅补一个接口。
4. 清单本身限定本次目标范围，因此导入时总量上限设为0以处理完整清单；保留面板当前每批数量和节点间延迟，跨节点最低15秒。
5. 重采成功的节点进入正常ZIP；仍失败的节点整节点丢弃，任务结束时产生新的失败log。新清单仅包含本轮仍失败的节点，可再次导入。

导入按完整商城＋类别＋商品类型＋节点ID去重；同节点ID在不同父级下不会混合。普通运行日志、残缺/损坏日志、不支持的格式版本、数量不一致和节点路径冲突会拒绝，并且不发采集请求。0条失败清单无需重采。最大50MiB、10,000条；仅导入明确的路径字段，文件中的URL、请求头、设置或代码不执行。

## 采集与界面

- 默认每批50成功节点，总数量0表示不限。四级循环与从当前项到末尾规则保留；后续父级从子目录首项开始。
- 页面`document-start`安装四级getFilters监听，页面加载只准备目录，点击开始后才采集。
- 同节点四请求紧接并行，不跨节点并行。默认节点间15–45秒，最低15秒。
- 业务请求首次60秒；发生超时后该接口的即时重试阈值为120、180、180秒。其他暂时错误的即时重试仍60秒。重试耗尽后符合条件的失败接口延后至少30秒再串行补一次，阈值180秒；切换节点仍遵守配置延迟。
- 401/403继续停止整个任务，429继续冷却/停止，不会为继续遍历而持续请求无权限或被限流的接口。
- 开始、终止、继续任务、动态进度、多选列表、全选/反选、下载/真实删除、日志下载/清空、最小化及列表/日志高度分隔条全部保留。
- 手动删除不会加入失败清单，迟到响应不能恢复被删除记录；删除已成功节点不退还当前成功数量预算。
- 原始JSON和NODE命名保留。NODE和报告保留逐次请求历史；成功数据只导出完整节点，不再导出部分成功节点。

固定安装与更新地址保留，需禁用旧采集器后在原Tampermonkey编辑器完整替换并刷新。初次建议选小范围，验证一份失败清单的下载与导入。不要同时运行节点映射采集器的任务。

## 存储与下载边界

沿用数据库版本2，兼容原批次与任务；启动时清理旧归档及隔离正文。旧任务已完成但不完整的节点会转换为失败重采信息并丢弃其原响应；尚在处理中断的节点仍供继续任务使用。新任务采用本版成功计数和失败清单规则。

下载只能确认已触发，不能确认磁盘落盘。请允许该页面多个文件下载，同时检查ZIP和失败log。失败log自动下载被拦截时，可点击“下载失败重采 log”补导出；开始新任务前请先保存所需清单，当前任务的失败元数据会由新任务替换。日志清空不影响失败清单。

数据、节点路径和日志都属于业务信息，分享前检查；脚本不保存Cookie、认证头、失败响应正文，也不上传额外遥测。已删除节点正文无法从脚本补回。
