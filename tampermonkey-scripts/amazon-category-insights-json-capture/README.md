# Amazon 类目洞察数据采集器 · 7.0.3

在 Seller Central 类目洞察页面主动请求类目表现、产品特征、畅销 ASIN 和新品 ASIN，导出原始 JSON ZIP。

## 安装与更新

固定安装地址：<https://tools.aioz.cc/tampermonkey-scripts/amazon-category-insights-json-capture/amazon-category-insights-json-capture.user.js>。

已配置 `@updateURL` 和 `@downloadURL`，由 Tampermonkey 按用户设置检查更新。也可在原脚本编辑器中完整替换代码、保存并刷新。只启用一份类目洞察采集器；旧版首次接入更新地址仍需手动替换。

## 使用

1. 打开 `https://sellercentral.amazon.com/selection/category-insights`，选择商城、类别、商品类型和关键词。页面加载时同步监听四级 `getFilters` 准备目录，不自动发起业务采集。
2. 选择自动遍历范围：关键词必选，向外可包含商品类型、类别、商城；从当前项到末尾，进入后续父级后从子目录首项开始。任务范围在开始时锁定。
3. 点击“开始抓取”。同一节点四个数据请求紧接并行发出，不点击 GUI，不跨节点并行。每条响应绑定完整任务路径。
4. 默认每批50节点，总量0表示不限；节点间随机延迟15–45秒，最低15秒。可先将总量设为1检查下载结果。
5. 保留四级动态进度、倒序多选列表、全选/反选、下载选中、节点下载、删除选中/全部和运行日志下载/清空。“终止抓取”取消等待和可取消的在途请求；尚未下载的数据支持继续未完成任务。
6. 标题栏“−”最小化为标题按钮，点击恢复，采集继续运行。拖动列表与日志之间的横向分隔条，调整固定窗口内两块区域的高度比例；窗口恢复和数据刷新保留本页比例。

## 空响应与异常

v7.0.3 修复 Features 合法空响应 `{"featuresName":null,"featuresList":null}` 被误判为结构错误的问题，现记为“无数据”，原始 JSON 正常导出。空 `featuresList` 数组继续兼容，其他未知结构仍显示失败。

关联 ASIN 中业务字段为空且 `relatedASINs: []` 时按明确空响应处理；存在聚合指标时仍算有数据。HTTP 204记为无正文，不伪造JSON。performance失败不能算节点成功，可选接口失败记为部分完成。

每请求默认60秒超时；网络错误、超时及可重试5xx最多重试3次，只补失败接口。429统一冷却，遵守Retry-After，否则至少60秒并附加随机延迟；冷却后的重试波次再次429则终止。401/403停止后续调度。错误只保留状态、原因和日志，不保存异常响应原文。

## 下载与删除

- 有效原始 JSON（包括明确空响应）正文不改写，保留节点目录、JSON命名、NODE元数据原字段，并附任务和接口状态报告。
- 自动分批、收尾或手动下载成功触发后，清除对应节点的内存、IndexedDB正文、批次和单节点结果记录，不保留历史补下载副本。脚本无法确认文件实际落盘，请允许浏览器多个文件下载并检查下载记录。
- 手动删除需确认，执行相同的真实清理；迟到响应不能恢复已删除节点。新任务可重采相同节点。
- 打包、触发下载或清理事务失败时保留尚未清理的数据并报错。任务总体进度、累计计数和运行日志保留，删除不退还本任务数量预算。
- 已移除“历史补下载”和“隔离响应”功能。首次加载会清理旧版已归档副本和旧隔离原文，保留未下载数据；旧数据的该项清理不可恢复。
- 继续使用IndexedDB `amz_category_insights_capture_v1`版本2。旧`quarantine`表仅作兼容而保留为空，不再写入异常正文。v6.7.0使用数据库版本1，不能直接读取升级后的库；v7.0.x之间无需再次升级数据库。

脚本不保存Cookie、认证头或完整请求头，也没有新增上传或遥测。数据和日志包含业务信息，分享前需检查。

只匹配 `.amazon.com` Seller Central 页面，不扩展其他域名。自动更新、真实页面和请求兼容性取决于实际浏览器环境。

fflate 0.8.3 已内置，无远程 `@require`；许可证见 `LICENSE-fflate.txt`。
